# Writing Anti-AI Loop

整篇论文逐章改写，迭代到文风不再变好为止。改写规则全部来自 `writing-anti-ai` 和 `PROSE.EXPLAINING_REGISTER`（六原则），正文段落（含脚注）的句中冒号与分号一律禁止，锁、六原则和保真都不能豁免。本 skill 只负责编排：分章、派子代理、每轮审改动、核保真、核规则、打分、决定停不停。

claude-scholar 根目录是本 skill 目录的上两级，下文记作 `$CS`。

## 共同目标与前提

目标是在保留技术命题和必要披露的前提下，让目标读者准确、顺畅地理解已有内容。六原则用于发现和修复具体表达障碍，不按主语、语态、从句、情态词或连接词的数量判定质量。每个拟修改项说明原文位置、具体理解障碍、稿内依据和解决标准；按章节职责与必要上下文判断，已清楚可保留，依据缺失或解释不唯一时报告。

验收维度为表达清楚、关系连贯、信息适量、用语准确自然；保真与作者偏好合规单独核查。六原则及共同操作管怎么改，四维度管效果，执行过规则不等于合格。

- 表达评估可以由带上下文的阅读完成，不依赖打分服务。需数值时用固定单元的表达验收通过率，同时报覆盖率、重大问题和待核项。未检查不算通过，同稿比较须固定单元对应，不能以拆段或加字增加通过率。
- `P2G_STYLE_URL` 可选，仅返回年代诊断时不能冒充表达分。已有评估可传 `scripts/score.py --evaluation <json>`；无评估则显示未评，不退回词率主分。没有服务也按具体问题决定是否继续，不强制跑两轮。
- 服务请求会上传稿件。仅在作者已授权该服务处理稿件时调用；本机评读无需这一步。不得因配置了 URL 就自动获得上传授权。
- 有 `latexmk` 时每轮编译一次；没有则注明版面未验收。

## 准备

1. **只在副本上改。**在论文目录旁边建 `<论文名>-anti-ai/`，里面放：
   - `orig/`：原稿的完整拷贝，之后不再动；
   - `work/`：当前版本，子代理只改这里；
   - `r1/`、`r2/`……：每轮结束时 `work/` 的快照；
   - `LOG.md`：每轮的分数、保真结果、回退了哪些改动。

   拷贝时只排除编译产物（`.aux` `.log` `.bbl` 和编出来的论文 PDF），图片要留着，包括 `.pdf` 格式的图，否则编译不过。下文的 `main.tex` 指论文的主文件，不叫这个名字时换成实际的文件名（例如 `main_sp.tex`）。
2. **分章**：`python3 scripts/split.py split <out>/work/main.tex <out>/chapters`。它把 `main.tex` 切成连续的几段：导言区、摘要、每个 `\section` 一段、参考文献起的尾部。`parts.json` 里标 `edit` 的才交给子代理。
   - 多文件论文：`main.tex` 里通常只剩摘要可改，各章就是 `\input` / `\include` 的那些文件，子代理直接改 `work/` 里的章节文件。
   - 单文件论文：每个 `\section` 一段，子代理改 `chapters/` 里的段落文件。
   - 每轮子代理改完，先 `python3 scripts/split.py join <out>/chapters <out>/work/main.tex` 拼回去，再做后面的检查。拼回的文件保持原稿的版式。
   - 附录照常算章。不到 150 词的节可以和相邻的节合给同一个子代理。
   - **派发前确认结构**：主代理先确认论证主线和跨节重复。仅发现段落必要性、位置或跨节分配问题时，调用 `claim-architecture-review` 做定点审查，记录保留、搬移或去重的落点后再派逐章改写；已有 `spine.md` 就复用，没有则只补理解该问题必需的主线。只处理已定位的问题，不扩大成重写论文或改贡献。
   - **章节功能与粒度**：每章先写一句读者任务。摘要交代问题、方法、规模、核心发现和贡献，只留理解发现必需的数字、条件和边界，不逐项展开原因、区间和次级计数。结论交代确立了什么、边界与下一步，不复演实验。方法和结果讲步骤、证据与关系；讨论讲行动者和适用条件。
   - 减少重复细节前，逐项记录同一事实在正文或表图中的准确位置。唯一结果、必要限定和核心发现不能删。长度和数字量只作诊断，不按范例设配额。
   - **段落任务**：按六原则卡「六原则的共同操作」诊断，既查**内容未接齐**，也查**内容已在但压进句内结构**，包括前置修饰串、嵌套所属和名词化。改前只列有问题的段落，每段一句「读者要补哪一步关系—已有来源在哪里—准备怎样重组」；压缩疑点定位到具体短语，来源定位到全文已有段落或表图。找不到依据或解释不唯一就报告，不编原因。这个记录用于定位任务，不要求每段填长台账、套同一种形状或凑改动数。
   - **全文篇幅分配**：记录作者批准的全文页数或篇幅及其来源，先写出最短的清楚表达，再核全文版面并协调解释与去重的空间。去重须保留读者在本处理解结论需要的分母、实例和限定，不能只确认别处仍有同一事实。章节增长可由别处删重复抵消，不能删事实补预算，也不能自行放宽全文上限。放不下时报告具体冲突及未解决句子，不把关系压回名词串来满足局部词数；每轮仍编译验收。
3. **基线**：`python3 scripts/score.py <out>/orig --main main.tex`，记进 `LOG.md`。

## 每一轮

### 1. 并行改写

每章一个全新子代理（Agent tool，`general-purpose`），**在同一条消息里一起派出去**。子代理之间不共享上下文，每轮都是新的子代理。

- **第 1 轮**：完整执行 `writing-anti-ai`，先按六原则改，再按 anti-AI 规则改，复核改动段落及保留疑点后停手。
- **第 2 轮起**：以六原则（`$CS/policy/rules/prose-explaining-register.md`）为改写主任务，按其「六原则的共同操作」逐段检查，不重跑完整润色。关系藏在句序或名词串里时，可调句序、拆合句、重组段落；单句或单条原则合格不等于整段讲清。已讲清的段落可不动。硬约束和新增改动每轮复核。已测稿件支持这个方向，不足以推断所有稿件重复完整 skill 都无益（E8、E9）。

子代理提示词模板（把 `{}` 换掉）。每条任务级硬约束都带规则 ID 或作者指令的可定位来源；工作范围约束注明本 skill 的小节。发出前核对实际 prompt 与模板的差异，新增条款缺来源就不发送。不从一次回退推导新的句式禁令或保留令，也不要求一组自然语言句子用同一种写法；术语和标签可以一致。

```
你负责改写 {file}（{chapter}），只改这一个文件{abstract_note}。
先读 {CS}/policy/rules/prose-explaining-register.md 和 {CS}/policy/rules/prose-negation-contrast.md。
{round_rule}
硬约束：
- [来源：writing-anti-ai-loop §准备、§并行改写] 只用 Edit 改 {file}。不建任何文件，不改其他文件，不跑会写文件的命令。
- [来源：writing-anti-ai-loop §核保真] 保真以命题为单位，不增删事实；数字可减少重复提及，不改引用、公式、\label 和 \ref 的目标。figure / table 环境、caption、公式、代码、\cite 键都不动。自定义宏（例如只在某个版本出现的 \extonly{…}）的调用和包住的范围都不动。区分事实消失、必要限定消失与同一事实少重复一次；记录同一论断在正文或表图中的准确落点，不能只凭数字字符串还在，也不能仅因本章不再精确报数就回退。坏结果、分母、范围和安全含义仍须显著、准确保留。caption / table 不在本次标点检查范围，只报已排除计数；其他受保护正文若违规，只报告冲突，不据此放行。
- [来源：PROSE.EXPLAINING_REGISTER、PROSE.HEDGING_DISCIPLINE] 不改变论断的强度、条件和范围。只用整篇论文已明确给出的解释、原因和关系；跨句或跨节移用要注明来源。同一关系换结构不算新增事实，推测不能当已写明的原因。原意不清时报告。
- [来源：writing-anti-ai-loop §并行改写；有作者要求时填 {length_source}] {length_rule}
- [来源：writing-anti-ai-loop §不要做] 只按规则和读者任务改，不按词频改。
- [来源：PROSE.EXPLAINING_REGISTER、PROSE.NEGATION_CONTRAST、PROSE.MIDSENTENCE_COLON、PROSE.SEMICOLON_RESTRICTION、PROSE.EM_DASH_RESTRICTION] 命题保真始终有效，锁、六原则和保真都不能豁免正文冒号与分号硬禁令。不能兼得时报告具体冲突，不删论断、不报通过。rather than / instead of 先核定义／范围的必要区分，其余按三判据逐条给依据，不能因入锁就保留。
改前任务（来源：writing-anti-ai-loop §准备）：
按六原则卡「六原则的共同操作」检查内容未接齐和内容已在但压进句内结构两类问题；只列有问题的段落，每段一句「读者要补哪一步关系—已有来源在哪里—准备怎样重组」，压缩疑点指出具体短语。
回复（简述改动量和保留理由，尽量在 400 字以内；语义风险报告不受此上限限制）：
1. 改了大约几处；
2. 没改的段落，每段一句具体解释链；有压缩疑点却保留的句子，指出具体短语，说明其修饰关系、动作对象或指代为何能直接解析。「范围明确」「术语准确」「流程完整」或原则编号不能单独作为保留理由。改了的段落看 diff 和完整段落，不重复列台账；
3. 条件、强度、范围和关系有改动的，逐条给出原句和新句；去重注明命题保留的准确落点，语义风险不能为了字数省略；
4. rather than / instead of 的必要划界依据或三判据判定，以及原文里看到的事实问题（只报告，不改）。
```

- `{round_rule}`，第 1 轮：`再读 {CS}/skills/writing-anti-ai/SKILL.md，按它的执行顺序改：先按共同操作执行六原则，再 anti-AI 规则，复核改动段落及保留疑点，然后停手。`
- `{round_rule}`，第 2 轮起：`以六原则为主任务，按六原则卡的共同操作逐段检查，必要时重组段落。不重跑完整润色；硬约束和新增改动每轮复核，完成后按 writing-anti-ai「执行顺序」查反向压缩。`
- 第 2 轮起，只锁有回退记录的原句。`locks.json` 用对象数组，每条必填 `sentence`（原句）、`orig`（相对台账或绝对路径）、`rollback_round`（正整数）、`rollback_reason`、`proposition`（含条件和强度）。`python3 scripts/guardrails.py locks <out>/locks.json` 核对原句逐字存在于 orig，输出原文哈希和位置；可填 `orig_sha256` 固定基线，变了就拒绝。旧式字符串数组、缺字段或找不到原句都拒绝。
- 机器只能验证原文来源，不能凭五个字段证明真实回退。主代理另核对该轮 diff / 回退记录确实恢复了原句，记录证据位置；未经这一步不得派发。不要给旧数组补个来源标签就算重建完成。
- **锁保护命题，不保护语法外壳。**原句含零容忍候选时标「只锁命题」，不能要求逐字保留；换成合规结构。其余锁默认不动，若阻碍六原则重组，改写者给保义候选和理由，主代理按「审改动」核对实际语义变化；不能因某个候选的局部失败锁死原来的语法结构。
- 作者批准的事实修复单列语义基线、批准来源；后续保真对照批准版本，orig 不动，不冒充回退原句。
- `{abstract_note}`，摘要那一章：`，并且只改 abstract 环境`；其他章为空。
- `{length_rule}`：`按准备阶段分配给本章的解释与去重任务调整篇幅，先写最短的清楚表达再核版面，以作者批准的全文页数或篇幅验收。去重保留本处理解所需的分母、实例和限定，放不下报告具体冲突，不压回名词串；章节增长可以由别处删重复抵消，不能删事实（见「准备／全文篇幅分配」）。`填入具体全文上限、作者来源及本章分配；未提供上限时沿用当前已批准要求，无可确认要求则报告篇幅变化，不自设逐章上限。每轮编译核对页数，词数不能代替版面验收。

### 2. 审改动

主代理负责，不交给子代理。

1. 看改前的问题定位和改后没改段落的理由：按回复第 2 项复核具体解释链及保留的压缩疑点，不能只贴原则编号；理由站不住时重新定位问题。逐条看回复第 3、4 项。**保真保护命题，不保护语法外壳**：换主语、名词化改动词、显式写出原有条件，本身不算改变命题。因保真回退须指出行动者、对象、量化、条件、因果或证据强度的具体变化，不能只报换了主语或加了 `can` / `may`。语法挂靠错误等局部失败，先给一次不增事实、不弱化限定的保义修复机会，仍失败再回退，记录仍未解决的歧义；在 `LOG.md` 记录修复或回退理由。无依据的新事实不得保留。
2. 逐章读本轮的 diff（`git diff --no-index --word-diff <上一轮> <out>/work`）。重点看：
   - 条件和范围：原来不限定的论断被加了条件，或者反过来；
   - 新出现的因果和推论；
   - 数字换成回指（「this rate」）以后，读者在本处还能不能理解结论所需的分母、实例和限定，不只查能否在别处找到原值。
3. **最终关系复核**：首轮在第二个 pass 后，后续轮在改写完成后，按六原则卡「共同操作」第 5 步比较改动段落，并复核未改却有压缩疑点的句子及其保留理由，读完整段落；不能只复核改动段落。按 `writing-anti-ai`「执行顺序」检查反向压缩，不能只凭数字齐全验收；原有原因、对照、限定须仍明确，只换语态或重复标题不算改善。回退或保义修补后，对受影响段落再做此检查，不扩成全文长台账。
4. 子代理报告的原文事实问题不在这里修，收进最终报告交给作者。

### 3. 核保真

```
python3 scripts/fidelity.py <out>/orig <out>/work
```

- 退出码 1：引用键或 `\label` 出现或消失、`\ref` 指向原文没有的标签，或者出现了 `NOT IN ORIGINAL` 的数字或公式。逐项处理：新事实改回原文；只是把原文里的值说明白了（例如原文 `$W\in\{1,2,5,10\}$`，改写写出 `$W=10$`），在 `LOG.md` 里写明理由后保留。
- 丢失的数字只报告，不自动算失败。逐项区分「事实消失」「必要限定消失」「同一事实少重复一次」：前两种必须修复，后一种还须通过「准备／全文篇幅分配」的本处理解检查。同一论断已在正文或表图中准确保留，不能仅因本章不再精确报数就回退；记录其对象、分母、条件、强度及落点，不只比数字字符串。坏结果、范围和安全含义仍须显著、准确保留，不能用含糊回指掩盖。局部挂靠等错误先按「审改动」保义修复一次，失败再退。

### 4. 核规则

每轮审改动、核保真后执行，过关才打分。第 2 轮不重跑完整润色，不等于停查硬约束。

```bash
bash "$CS/policy/lint.sh" <out>/work
python3 scripts/guardrails.py <out>/work/main.tex --json <out>/rules-rN.json
```

- 完整 lint 与候选枚举不能互相代替。枚举从摘要到参考文献前的全部正文，含脚注、列表、宏参数和输入文件；caption 和 table / tabular（含输入的表格文件）排除，只报已排除计数，不计候选或违规。仅非散文豁免也计数，含数学、代码及 `\texttt` / `\verb`、`\;`、URL、时间、引用键和结构标题冒号（含段首 `\textbf{TV-1: Static extraction scope. }` / `\paragraph{...}`），不能整块跳过盒子、括号或未改内容。
- JSON 记录文件、行号、规则 ID、源哈希、正文范围与各类计数；简表输出到 stderr。退出码 0 为无候选，1 为有候选，2 为解析或覆盖失败。对照候选仍需按规则卡判档；脚本不代替语义判定，也不执行 TeX；支持静态 input/include 与源码中的宏参数。调用的自定义宏若在定义中藏了候选，报覆盖错误，展开后复核；不能据此宣称生成文本已全覆盖。
- 正文冒号和分号在明确豁免之外一律记「违规」，不再有「待判断」；列表末尾和直接引语不豁免。em-dash 照旧，档 A 对照仍可待判。非散文记明确豁免及理由，caption / table 仅报已排除计数。违规与待判断都为 0 才通过；无输出、空正文、空章节、漏摘要或解析失败一律失败。范围内的受保护正文也要报告冲突，不能静默放行。分号修法为断句或按规则卡改成逗号加连接词。
- 回退、合并、换快照后重新跑最终文件。旧报告不可复用；`--check-report <旧报告.json>` 可核对输入哈希，变化时报覆盖错误，仍会重新枚举。
- 失败时只把原句、位置和规则交回改写者，不给分数或检测器信息。每轮至多补修两次；仍失败则保留最近合格版本，汇总未解决项，不报完成。
- 批量清标点或展开解释后，组合检查新句是否套同一框架。按 `PROSE.CAUSAL_CONNECTIVE` 判断关系，不因词多换同义词；同一关系可用同一连接词，不同关系不能靠同一词掩盖。新增计数、因果、闭合列举和情态逐项回原文核对，需要重写的交回改写者。

作者 2026-10-21 定为硬规则，用来取代逐条判断；MSR 一稿因为逐条判断加上锁，违规句一路存活了 11 组。

理由：MSR H 组自报零命中，摘要的 “]; 54.2” 仍在；G 检出 14 处不证明覆盖完整。F 新增 11 个 therefore、H 七句同框架说明组合验收也不能省；这些次数不构成新禁令（E12）。

### 5. 编译和打分

- 有 `latexmk` 时编译 `work/` 的一份临时拷贝。未定义的引用和 ref 必须是 0，记录正文终页、参考文献起页和总页数，不只记总页数。有页数要求时按编译验收；临时放开要记作者来源，标「内容候选，版面未通过」，不能称可投稿完成版。
- 有 PDF 时查段末一两词的悬浮行、溢出和浮动体。先尝试不改文字的排版修复；改文字就重跑保真和规则。不删目的、情态、条件或精确限定来省一行。
- 已有表达评估时用 `python3 scripts/score.py <out>/work --main main.tex --evaluation <本轮评估.json>`。文件必须携带逐单元判断和源文件哈希；脚本拒绝陈旧来源，不接受只给一个分数的文件。
- 已授权服务可另取 `era_similarity`、`era_similarity_bounded`、`wording_per_1k`、`words` 和 `gain_top3_share`。均只作年代诊断，不设置涨分门槛，也不能据变化集中度否决已确认的改善。
- 保存 `r<N>/` 快照，`LOG.md` 记录具体改善／退化、表达评估范围、保真、规则、版面结果和诊断值。评估未完成就明确记未评。

### 6. 停不停与选稿

- 有明确、能保真解决的表达障碍才继续定点修改。没有这样的障碍，或本轮没有可确认的改善，就停，记录未解决项。不为了跑满轮数制造问题。
- 最多 4 轮（含第 1 轮）。达到上限表示本次处理结束，不代表全文合格；未解决项仍需报告。
- 不沿用旧 80 分门槛、涨幅不足 1 分停手或最高分优先。年代诊断、虚词变化集中度、单元数量及篇幅变化均不能认证质量。
- 用保真核查及带必要上下文的比较决定采用改动；可做盲读时隐藏版本标签和分数。局部改善与退化并存时逐项选择，再复核组合文本，不自动选整轮最高分。没有可确认差别时保留原表达。
- 采用版本须同时满足规则与当前版面要求。超页先处理具体空间冲突，不将其称为“没涨分”。未编译且有页数上限时版面仍待验收。

选定或组合后复制回 `work/`，重新核保真、规则、段落关系及版面。没有合格快照时交付未通过项，不称完成；若选择了某个局部改动，说明它减少了哪一步推断及保真依据。表达通过率只汇总固定单元的已完成判断，重大条件／分母／保证范围问题单列，不被其他单元抵消。

## 不要做

- **不把分数、分数的变化或检测器的任何信息告诉子代理。**子代理只读规则卡。
- **不根据检测器去写规则。**哪些词被计分、各占多少，不能成为新规则的来源。规则只能从「作者在为读者做什么」出发；新规则先在没参与制定它的论文上验证解释是否更清楚。年代相似度与变化集中度均不能认证或否决质量改善。
- 不为了涨分把正文里的数字挪进表格，也不删正文里的结果。第 5 条允许减少在正文或表图中已有准确落点的同一命题的重复提及，不允许丢结果或必要限定。
- 不发送无规则或作者来源的硬约束，不给自然语言句组规定统一句式。
- 不在子代理之外自己逐句改写来追分。主代理只做回退和保真修补。
- 不碰原稿，不 push 到 Git 或 Overleaf，除非作者明确批准。要推到 Overleaf，建议把改写放进 `rewrite/sections/` 再加一个 `main-rewrite.tex`，主稿不动。
